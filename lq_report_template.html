Native FP8 support and causal correctness
The streaming adapter preserves the original first-frame replication, temporal padding, prior-cache reads, two-frame cache snapshots, and cache updates. BF16 layout mode preserves channels-last-3D through intermediate operations; explicit conversions are included in timing. FP8-only mode changes Conv3D 2 and performs the layout conversions required by the native kernel; BF16 Conv3D 1 remains untuned. In combined mode, Conv3D 1 is autotuned BF16 and Conv3D 2 uses cuDNN native FP8 heuristic A/fallback plan selection; both paths preserve 3D channels-last. No BF16 fallback is used by the FP8 adapter.


Validation details and reproduction
Run bash run_lq_study.sh from the provisioned workspace, using fresh output directories. Pinned weights, upstream source, six inputs, and the saved head-retention policy are required. The source snapshots are in source/. The suite generates the clips, records profiles, then scores fidelity; build_lq_report.py builds this report.


Measurement limits
Full-video generation uses one timed pass per clip and configuration, in control → BF16 layout → FP8 Conv3D 2 → combined order. Warmed component measurements use three repeats with rotated order. Small full-pipeline differences may be noise; this study does not establish statistical significance. The attention policy was previously calibrated on female_default and male_existing. No new attention calibration was performed. The four-clip reference option exposes held-out fidelity.
All six fresh control videos are byte-identical to the previous requested-stack outputs; hash evidence is retained. Shivam’s reference videos are checked against the original published SHA-256 hashes. Each generated output passes frame count, resolution, full decode, and original audio-packet/timestamp integrity checks. All configurations share source inputs, seed 2026, preprocessing, model weights, frame geometry, and encoding.
